# KPL BP 数据平台

从「全局 BP 模拟器」扩展而来的王者荣耀 Ban/Pick 数据平台，包含五个模块：

| 模块 | 功能 |
| --- | --- |
| **模拟推演** | 原 v1 全局 BP 模拟器（BO3/5/7、全局锁定、巅峰对决），进度存 localStorage |
| **比赛录入** | 选择赛事/赛段/日期/战队/出场阵容后，**按真实 BP 顺序点一遍**完成记录，自动保存 Ban 顺序、选人楼层、选手-英雄对应（选人默认**按英雄分路预选同位置选手**，主位置被占自动回退次分路，可点选改人；**可按局更换出场选手**，与系列赛阵容不同的局单独记录，统计与全局 BP 锁定按当局出场阵容计算（全局 BP 为**整队锁定**口径））；蓝红方逐局轮换（可手动调整），**BO7 第 7 局**自动巅峰对决（BO5/BO3 末局为普通局）；支持**空禁**（放弃某条 Ban 占位）；英雄池搜索支持**拼音/首字母**且**焦点自动回到输入框**，可用 **↓←→↑ 方向键选择、回车确认**（左右首尾环绕），全程键盘流；战队选择支持**拼音搜索**（"fs"/"drg" → 佛山DRG）；阵容可从**大名单点选**或**一键填入上一场首发**；新建表单默认带**当前赛事**（最近有录入的）及上次的赛段/日期/赛制；**前置条件：本赛事全部参赛战队登记大名单后才能开始录入**；**支持同时进行多场录入**（工具栏「暂存并返回」留草稿退出，列表每张草稿卡可继续）；录入过程**草稿自动保存**（浏览器本地），误关/刷新后可从列表页继续；**未录完也可保存**（「保存已录 X 局」：已完成局入库，之后从列表「继续录入」补录）；工具栏「快速完成本局」可随机补全剩余 Ban/Pick（测试辅助，胜者仍需手动标记）；列表**按赛事筛选**（默认当前赛事）、支持**编辑元数据（赛事/赛段/日期/备注）**、回放（含**单局胜者改判**、**局间换人标注条**）、删除；回放/编辑及各弹窗支持 **Esc 退出** |
| **大名单** | 每赛季（赛事）为各战队登记选手名单：前 5 位按位置顺序（对抗/打野/中/发育/游走）、之后为替补，支持整段粘贴；「**参赛战队**」弹窗先确定本赛事参赛队伍（数量→逐槽选队，可当场**新建战队**，整体替换）；「＋**新建赛事**」快捷入口；总览表显示各队登记进度。比赛录入时直接点选首发，避免缺人/漏人/错名 |
| **数据分析** | 按赛事/赛段/日期/战队筛选，五个页签：总览（Pick / Ban-Pick / Ban 三榜）、英雄（含主分路筛选、全 KPL 两/三/五英雄组合榜、Counter 关系）、战队（全部战队总览表 + 单队深看：蓝红方胜率、Pick/Ban 偏好、两两与三位置组合胜率、落败选边）、选手（全表可排序、可搜索）、赛事分析（按备注的轮次对比、跨赛事对比） |
| **基础数据** | 战队/选手/赛事管理 |

> 赛程排期页已移除（内容被比赛录入覆盖）。录入保存仍会自动维护数据库中的
> schedule 镜像行（赛程表继续随录入/删除联动）；如需恢复排期管理，从历史版本找回 SchedulePage 即可。

界面支持**浅色（默认）/ 深色**双主题，顶栏一键切换并记住偏好。

## 运行

```bash
npm install        # 首次
npm run dev        # 开发模式：同时启动数据服务(:9100)与 Vite(:5173)
npm run build      # 构建前端到 dist/
npm start          # 生产模式：单进程，数据服务直出 dist（http://localhost:9100）
npm test           # 纯函数回归测试（BP 校验/轮次/大场胜负/组合/阵容语义/英雄搜索）
npm run status     # 数据与服务现状一览（两库计数、9100/9101 是否在跑）
```

> 环境要求：**Node ≥ 22.5**（后端使用内置 `node:sqlite` 模块，无原生依赖）。
> 端口说明：数据服务默认 **9100**（Windows 下 5173/5174 等常被 Hyper-V
> 动态保留导致 EACCES）。如需更换：`PORT=9000 npm start`（开发模式
> Vite 代理会读取同一 `PORT` 环境变量）。

## 测试环境与生产同步

生产环境（**9100** / `data/kpl.db` / `dist`）与测试环境（**9101** / `data/kpl-test.db` / `dist-test`）完全隔离，页面右上角有红色「测试环境」徽标防混淆：

```bash
npm run build:test              # 构建前端到 dist-test
npm run start:test              # 启动测试环境 http://localhost:9101
npm run start:test -- --reset   # 启动前清空测试数据库（重新预置战队/选手/赛事）
```

或双击根目录 `启动测试环境.bat`。把当前生产数据复制到测试库：`npm run copy:test`
（需先关闭测试服务；使用 sqlite 在线备份，生产服务运行中也可执行）。

> 注意：`npm run dev` 和 `npm start` 连接的都是生产库 `data/kpl.db`，
> 只有 `npm run start:test` 使用测试库 `data/kpl-test.db`。

改动验证与同步生产流程：

1. 改动先在测试环境验收：`npm run build:test`（改了 `server/` 需重启测试服务）
2. 确认无误后同步到生产：
   - **前端改动**：`npm run build`，9100 刷新页面即生效
   - **服务端改动**：重启生产服务（关闭数据服务窗口后重新运行 `启动.bat`）

## 数据存储

- 数据库：`data/kpl.db`（Node 内置 `node:sqlite`，零原生依赖），可直接复制备份
- 首次启动自动预置 18 支 KPL 战队（2026 赛代名单，见 server/db.mjs PRESET_TEAMS，
  可在「基础数据」页改/删）与 10 个选手昵称作录入提示，不代表任何当前阵容
- 录入系列赛时，阵容中出现的新选手名会自动进入选手库
- 「基础数据」页管理战队/选手/赛事；备份直接复制 `data/kpl.db` 文件即可（服务启动时也会自动快照到 `data/backups/`，保留 14 份）

### 数据模型

```
teams(id, name, short)          战队
players(id, name)               选手库（录入提示用）
events(id, name)                赛事（如 2026 KPL春季赛）
series(id, event_id, stage, date, bo, team1_id, team2_id,
       roster1, roster2, note)  一场系列赛；roster 为 5 人 JSON（按位置 0-4）
games(id, series_id, game_no, blind, blue_team_is_1,
      winner_side, roster1, roster2, draft)   一局；draft 为完整 Ban/Pick 顺序 JSON；
                                    roster1/2 为本局出场阵容（逐局换人时才有值，null=沿用系列赛阵容）
schedule(id, event_id, stage, date, time, team1_id, team2_id,
         status, series_id, auto)   赛程；录入完成后 status=recorded 并关联系列赛；
                                    auto=1 为录入联动自动生成的镜像行（删系列赛时随之删除）
pending_imports(id, ...)            同步待审表（未使用，遗留）
event_teams(id, event_id, team_id)  赛事参赛战队（无记录=未设置，前端回退全部战队；无外键，删除时接口顺手清理）
```

### 数据修正入口（全部在页面完成）

- 录入列表「编辑」：修改日期/赛段/赛事/备注（对阵与选手只读；换人走回放「编辑BP → 更换选手」）
- 录入列表「继续录入」：**胜场未达标的系列赛**（如误标胜者导致比分不对、或比赛尚未打完）可在原系列赛上补录后续小局，蓝红轮换自动接续
- 完成页「撤销上一局（改判胜者）」：标记胜者后发现点错，可退回上一局重新标记（系列赛结束页同样有）
- 回放弹窗「编辑BP」：把该局载入 BP 编辑器（撤销/重做/互换选手/**更换本局出场选手**/换蓝红/**改判本局胜者**），保存只更新该局草稿、阵容与胜者，不影响其他局
- 回放弹窗「改判」：单局胜者快捷修正（改判后若比分不再达标，列表会重新出现「继续录入」）
- 删除：系列赛删除后其关联赛程自动恢复“未录入”；BP 内容录错则「编辑BP」修正或删除重录

> 历史遗留：`npm run sync`（官方/URL/文本 JSON 抓取→待审区）链路**未使用、不再维护**（用户不需要
> JSON 导入），文档不再展开；相关代码（scripts/sync.mjs、server/adapters.mjs、/api/sync 端点）保留在原处。

位置约定（录入阵容时按 1-5 顺序填写）：**对抗路 / 打野 / 中路 / 发育路 / 游走**，
组合分析（上野/中野/中辅/射辅等 10 种两两组合）基于该位置顺序计算。

## 分析口径

- **Pick 率 / Ban 率**分母 = 2 × 局数（每局每队各一次机会）
- **Ban-Pick 率** = (Ban 次数 + Pick 次数) ÷ (2 × 局数)（该英雄在 BP 中出现的综合概率）
- **选用胜率** = 该英雄被选出且所在队伍获胜的场次 / 被选出次数
- **楼层** = 该英雄在所属队伍本局选人顺序中的位次（1-5 楼）；楼层分布列可按 1 楼次数排序
- **首 Ban** = 该方本局第一条 Ban（蓝方一ban 或 红方一ban 都计入，盲选局无 Ban）
- **组合** = 同队两个位置的英雄对（按出场次数与胜率排序；三位置组合同理）

## BP 规则（模拟与录入共用同一引擎）

- 常规局：每方 5 Ban / 5 Pick，顺序为
  Ban(蓝红蓝红) → Pick(蓝1 红2 蓝2 红1) → Ban(红蓝红蓝红蓝) → Pick(红蓝蓝红)
  （第二轮 Ban 红方先手、双方各 3 次）
- **空禁**：Ban 阶段可点「空禁」放弃该条 Ban（draft 中记 `hero: null`，占位不影响步数）
- 选人时**按英雄分路自动预填同位置选手**（主位置被占/锁定则回退次分路；均不可用时弹窗手动指定）；队伍面板**点击已选英雄可互换/移动**给其他选手（违反全局锁定会被拒绝）
- 英雄池对**本系列赛已用过的英雄**在"轮到用过的一方选择"时灰显、加"已用"徽标并**禁选**（整队锁定：该方任何选手都不可再选；对手回合照常可选）
- 全局 BP：某方用过的英雄，该方后续常规局**整队不可再选**（对手不受影响；巅峰对决解除锁定）
- 巅峰对决（**仅 BO7 第 7 局**自动触发，BO5 第 5 局、BO3 第 3 局为普通局）：无 Ban、蓝红交替盲选、解除锁定、双方可用相同英雄
- 修改流程顺序：编辑 `src/bp/rules.js` 的 `STANDARD_FLOW`；巅峰对决判定见 `isBlindDecider(bo, gameNo)`

## 英雄数据

来自官网 `pvp.qq.com/web201605/js/herolist.json`（含官方职业与分路标签），
头像来自 `game.gtimg.cn`，加载失败自动回退职业色块。英雄池搜索框支持
**拼音/首字母**（`gy`→关羽、`lvbu`→吕布；ü 按 `lv/nv` 惯例并兼容 `lubu` 写法），
拼音由生成脚本写入 heroes.json 的 `py` 字段（依赖 devDependency `pinyin-pro`，
未安装时刷新会沿用旧字段）。部分英雄的主分路按实况人工修正（脚本内
`LANE_PRIMARY`，如哪吒/夏侯惇/杨戬/元流之子·坦克/梦奇/猪八戒→打野、蚩奼/卢雅那→发育路、张良/赵怀真/墨子→游走），
生成时排到 `lanes` 最前，作为选人时的默认推荐位置。更新：

```bash
curl -sL https://pvp.qq.com/web201605/js/herolist.json -o scripts/herolist.raw.json
npm run refresh-heroes && npm run build
```
